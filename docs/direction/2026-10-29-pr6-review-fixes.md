# PR #6 리뷰 상위 4건 수정 (2026-10-29)

- **문제**: PR #6 리뷰에서 정확성 문제 4건이 나왔다. ① `external_run`이 wakeup을 먼저 지운 뒤 처리해, 예외가 나면 대화가 사라지고 lock 해제 뒤 재확인도 건너뛴다. ② 수집이 메일만 올리고 중단된 요청을 `reassign`하면 재수집이 같은 ID·다른 수신자 메일을 만들어 영구히 실패한다. ③ `reassign`이 새 주소가 요청의 워커 handle과 같아도 막지 않는다. ④ 실패 결과의 JSON 출력이 `--max-result-chars`를 무시한다.
- **풀 방향**: ① 처리하지 못한 대화는 wakeup으로 다시 써 두고, lock 해제 뒤 재확인은 예외가 나도 돈다. ② 열린 요청에 이미 올라간 회신 메일이 있으면 `reassign`이 그 메일을 그대로 마무리 기준으로 삼아, 재수집이 기존 메일과 같은 내용을 만들도록 회신 수신자를 기존 메일에서 가져온다. ③ 옮길 요청 중 handle이 새 주소와 같은 것이 있으면 아무것도 바꾸지 않고 거부한다. ④ 실패 JSON의 `result`에도 `shown`을 적용한다. 각 건에 회귀 테스트를 붙인다.
- **하지 않을 것**: 리뷰의 나머지 6건(공백 text, `--conversation` 없는 route, 없는 `--request`, 정리 2건, 방향 메모), 버전 올림·릴리스, 강제 푸시.
