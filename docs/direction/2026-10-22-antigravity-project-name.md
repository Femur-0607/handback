# Antigravity 사본 프로젝트 이름 — 방향 (2026-10-22, 이슈 #5)

- **문제**: Antigravity 2.23+는 전송용 사이드카마다 같은 폴더를 가리키는 사본 프로젝트를 만들고 사이드카 키(`handback-<요청 12자>`)를 그 이름으로 쓴다. 워커 대화가 등록한 프로젝트(`Study`)가 아니라 이 사본 아래에 보여서 사용자가 실패로 오해한다.
- **풀 방향**: 문서 보완과 첫 전달 출력의 프로젝트 표시는 d96d502에서 끝났다. 남은 것은 사이드카 키에 등록 프로젝트 이름의 영문·숫자를 소문자로 넣는 일이다(`handback-study-2650df801dea`, 남는 글자가 없으면 지금 형식). 옛 형식도 사본·정리 대상으로 계속 인정하고, 정리는 job.json에 기록한 키와 같을 때만 소유로 본다.
- **하지 않을 것**: 앱이 만든 사본 프로젝트 파일의 이름을 사후에 고치기, 사본 프로젝트를 즉시 지우기(대화가 사라진다), `status`·대시보드 표시 변경.
- **실측 (2026-10-22, Antigravity 2.24.0)**: `handback-handback-63d225be2c67` 키로 새 대화를 만들었다. 같은 이름의 사본 프로젝트가 생겼고, 대화는 그 사본에 속했다. 사이드카는 정리됐다.

## 후속 (2026-10-22, 0.5.0 배포 뒤)

- **문제**: 이름을 바꿔도 요청마다 사본 프로젝트가 늘어난다. 사용자가 원하는 것은 Codex처럼 등록 프로젝트(`handback`) 아래에 대화가 쌓이는 것이다.
- **풀 방향**: 사이드카 안에서 agentapi를 부를 때 `ANTIGRAVITY_PROJECT_ID`를 등록 프로젝트 ID로 넘긴다. 앱의 대화 목록에서 대화가 등록 프로젝트에 있는 것이 확인되면, 이번 사이드카의 사본(이름·폴더 일치, 대화 없음)을 백업 후 지운다.
- **하지 않을 것**: 예전 사본에 있는 대화 옮기기(앱 DB 수정), 확인 없이 사본 지우기.
- **실측 (Antigravity 2.24.0)**: 새 대화와 이어 보내기 모두 등록 프로젝트 `handback`에 남았다. 사본 `handback-handback-11cdb8cf069c`·`handback-handback-1041ff4842b9`는 전달 직후 지워졌다.
